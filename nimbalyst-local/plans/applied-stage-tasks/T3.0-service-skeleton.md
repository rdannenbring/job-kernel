# T3.0 — Applied service package skeleton

## 1. Purpose

Create the empty `backend/services/applied/` package with one module per Applied concern. Each module exposes its **public function signatures only** (returning `NotImplementedError`) so that downstream agents in T3a–T3h can fill in bodies in parallel without colliding on shared scaffolding.

This is the **gate** that unlocks 8-way parallelism for Phase A2.

## 2. Single-writer scope

You create the entire package in one PR. Each of the 9 files below is a stub. You do NOT implement function bodies — that's T3a–T3h.

## 3. Exact deliverables

### 3b. `backend/services/applied/__init__.py`

```python
"""Applied stage service layer.

One module per concern so multiple agents can implement them in parallel
without single-writer collisions. Each module owns its public functions; do
not cross-import bodies between modules unless re-exporting through this
file.

Decision log references (see ``nimbalyst-local/plans/applied-stage.md``):
- D1: contact alias (title → role) handled by Pydantic in
  ``backend.models.applied_models``, not here.
- D3: snapshot immutability enforced in ``submission.save_submission``.
- D4: overdue cached in ``follow_up_plan_json.status``; recompute on read.
- D5: every writer calls ``derivations.recompute_substage_cache`` at the
  end of its write path.
- D6: ``derivations.compute_sla`` returns ``None`` when no baseline exists;
  the route handler maps that to HTTP 404.
"""
from . import (
    derivations,
    state,
    submission,
    confirmation,
    follow_up,
    templates,
    contact,
    transition,
)

__all__ = [
    "derivations",
    "state",
    "submission",
    "confirmation",
    "follow_up",
    "templates",
    "contact",
    "transition",
]
```

### 3c. Stub modules — exact signatures

Each module file follows this template:

```python
"""<one-line purpose>.

Owner task: <Tx>. Do not implement bodies here unless you are that task.
"""
from __future__ import annotations

# Imports allowed: stdlib, sqlalchemy.orm.Session, backend.models.applied_models,
# backend.services.database_service (for the existing ORM classes only),
# and other modules in this package ONLY via the function-signature contracts
# below.
```

The exact signatures each stub must expose (return `raise NotImplementedError("T<x>")`):

**`derivations.py` (T3a)**
```python
def determine_applied_substage(app_row: dict | object) -> str | None: ...
def compute_completion(app_row: dict | object) -> dict: ...
def compute_sla(app_row: dict | object) -> dict | None: ...  # None when no baseline (D6)
def compute_next_steps(app_row: dict | object) -> dict: ...
def recompute_substage_cache(session, app_id: int) -> str | None: ...  # D5 helper
```

**`state.py` (T3b)**
```python
def get_applied_state(session, app_id: int, user_id: int) -> dict: ...
```

**`submission.py` (T3c)**
```python
def save_submission(session, app_id: int, payload, user_id: int) -> dict: ...
```

**`confirmation.py` (T3d)**
```python
def upload_receipt(session, app_id: int, file, user_id: int) -> dict: ...
def save_confirmation(session, app_id: int, payload, user_id: int) -> dict: ...
```

**`follow_up.py` (T3e)**
```python
def save_follow_up_plan(session, app_id: int, payload, user_id: int) -> dict: ...
def mark_follow_up_sent(session, app_id: int, payload, user_id: int) -> dict: ...
```

**`templates.py` (T3f)**
```python
def list_follow_up_templates() -> list[dict]: ...
```

**`contact.py` (T3g)**
```python
def upsert_contact(session, app_id: int, payload, user_id: int) -> dict: ...
```

**`transition.py` (T3h)**
```python
def transition_to_interviewing(session, app_id: int, user_id: int) -> dict: ...
```

Use the in-file `payload` parameter typed loosely (`object` is fine for now). Strong typing happens when each owner imports the appropriate `*In` model from `backend.models.applied_models` in their own task.
